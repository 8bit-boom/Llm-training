# The worker's contract (for nd-world)

nd-world embeds the training worker (`worker/ndforge_worker`) and starts it the way this program does: `python -m ndforge_worker <job.json>`, one JSON object per output line (see `protocol.py`).
What a consumer may rely on is written down in **`worker/ndforge_worker/contract.json`**:

```json
{"protocol": 1, "jobs": ["..."], "events": ["..."], "error_codes": ["..."]}
```

- `protocol` is the number the `hello` job also answers (`{"worker", "protocol", "packages"}`). It changes only when a line of the protocol changes its shape. Check it, not the package version.
- `jobs`: the values of `"job"` the worker accepts. `events`: the `"type"` of every line it may write (`log`, `progress`, `result`, `error` and the job-specific ones). `error_codes`: the `"code"` of an error line.
- **Names are only ever added.** A removed or renamed job, event or code breaks nd-world; `worker/tests/test_contract.py` reads the worker's code and fails when a listed name has disappeared, and when a new one is not listed yet.
- **Keys are only ever added, too.** A `progress` line may carry an additive `detail` (`{unit, done, total, rate, rate_unit, eta_s}`; without it the line is byte-identical to the older ones) and `reshape_try` takes an additive `want.search` (the automatic search; its `try_pass` events then carry `round`, `round_label`, `round_index`, `planned_total`, `budget_left_s` and `best`, and its analysis has a `search` key). No job, event or error code was added for them, so `contract.json` is unchanged.
- Consume the file, do not copy its words: read `contract.json` from the embedded worker and refuse a protocol number you do not know.

The Unsloth side: `tests/fixtures/unsloth/*.json` and `docs/UNSLOTH_API_CONTRACT.md` are meant to be identical in both repositories. `tests/fixtures/unsloth/SHA256SUMS` records the fixtures (of the text with LF line endings);
a test checks it, so a change to a fixture is always a conscious one. The workflow `contract-drift.yml` compares nd-world's copies with these (weekly, and by hand) when the secret `NDWORLD_READ_TOKEN` (a read-only token for
nd-world) is set; without it the job says "skipped" and passes. Nothing in nd-world is changed by any of this.

## The measured fit (added names)

New jobs `quantfit_estimate` (what the measured fit will do, from the header of a 16-bit GGUF only) and `quantfit` (measure, plan, optionally make the file and the plain sizes next to it; its result has `plan`, `report`, `rules`, `flags`, `files`, `measure_key`, `engine`, `notes`, `fits`), and the error codes `quantfit_failed` (a plain-language text) and `quantfit_stopped`; `llama_cpp_missing` is also used when a file is to be made and llama.cpp is not there. No new event. The export job also accepts the size id `mixed_measured` with the job key `mixed_measured` and answers with `mixed[<size>].measured`; the results of `quantcheck` gain the key `promotion` and the test text the kind `general`. Only additions: nothing was renamed or removed. See docs/MIXED_QUANTS.md ("Fit to a size (measured)").

## Healing in rounds (additive keys, experimental)

Healing in rounds (docs/HEAL_ROUNDS.md) trains a heal in short rounds and checks the thinking after each one. It needs no new job, event or error code, only new keys; `contract.json` is unchanged and a job without them behaves exactly as before.

- `distill_cache`: `upto_general_tokens` (answer the project rows and the general rows up to that many general tokens, then stop; the index stays `complete: false`) and `reuse_rows` (take the rows from `out/rows.npz` when the cache's own index says they are the rows of this run, without reading the general text again; needs `rows_key`). When the target rows are already answered the job returns before loading the teacher. Result keys `done_rows`, `general_rows_done`, `general_tokens_done`, `rows_before`.
- `distill`: `rounds` `{index, round_tokens, general_from, general_to, s_start, schedule?}` trains ONE round: the project rows and the general rows `general_from .. general_to - 1`, the optimizer and the scheduler continuing from the checkpoint of the previous round (HF's global step goes on from `s_start`). It writes `out/rounds/r<n>/adapter` and `out/rounds/r<n>/summary.json` besides `out/adapter` (the latest) and the result has `round {index, s_start, s_end, steps, tokens, calib_loss_after, complete}`. A partial teacher cache is accepted when it reaches `general_to`.
- `think_check`: `adapter` (a LoRA folder put on top of `model` without merging it; transformers backend only) and `double_quant` (a 4-bit base is loaded like the student is loaded for training). The cache key gets `adapter` (a hash of the adapter's content) and `double_quant` only when an adapter is given; without one the key is byte-identical to before.
- `think_check` / `think_check_plan`, backend `"vllm"` (EXPERIMENTAL, off by default, from a research report, not yet run on the owner's PC; see docs/VLLM.md): a new allowed `backend` value; optional `engine` object in the job (`kind` docker | docker_wsl | wslc | wsl | url | auto, `image`, `distro`, `venv`, `url`, `wslc` (command templates, syntax unverified), `hf_volume`, `quant` none | fp8 | a pre-quantized id, `version`, `extra_args`, `max_model_len`, `max_num_seqs`, `gpu_memory_utilization`) and optional `engine` object in the result (`vllm` version, `quant`, `lora`, `kind`, `ready_seconds`, `server_version`, `highlights`, `generate_seconds`, `completion_tokens`, `tokens_per_s`); `adapter` is accepted with `vllm` (served as a LoRA named `round`; DoRA and LoftQ adapters raise a plain message), `hf` works as before. The cache key gets `engine` only for this backend; the keys of `hf` and `llama` are byte-identical to before. The plan gets `startup_minutes` only for this backend. No new job type, event or error code.
- `think_check` with `backend` "vllm", an `adapter` and `fallback_hf` true (optional key): a vLLM problem or a DoRA / LoftQ adapter is answered by the standard engine; the result then has `fallback` (a plain sentence) and `backend` "hf".
- NEW job `trace_gen` and error code `trace_gen_failed` (docs/VLLM.md): `{"model", "backend": auto | vllm | llama | hf, "source": {"file"} or {"id", "split", "config"}, "column", "out_file", "limit", "max_new", "stop_file", "engine"}`; appends kept answers to `out_file` (jsonl, `messages` with `<think>...</think>` inline, `prompt_hash`) and rejected prompt hashes to `<out_file>.rejected.jsonl`; events `progress` step `trace` with `detail`; the result has `kept`, `attempted`, `rejected` per reason, `skipped_existing`, `backend`, `tokens_per_s`, `notes`.
- NEW job `vllm_container_probe` and error code `vllm_container_probe_failed` (docs/VLLM.md): `{"engine": {"container": {...}}}` (the engine settings of the other vLLM jobs); starts the idle container, moves a 1 KB file in and out by every way (bind mount of a host folder, `cp` in its variants, `exec -i` stdin), removes the container. Result `{ok, route_in, route_out, bind, tried: [{route, ok, detail}], seconds, text}`; the process exits 1 when `ok` is false. A `distill_cache` job with `engine.required` runs the same probe first.
- NEW job `vllm_selftest` (experimental, docs/VLLM.md) and error code `vllm_selftest_failed`: `{"model", "confirm_download", "engine", "out_dir", "stop_file", "quick", "gpu_test", "compare": {"hf", "llama", "hf_adapter"}, "adapter"}`; writes `vllm_selftest.json` and `vllm_selftest.md` into `out_dir`; the result holds the verdict (`pass | partial | fail | stopped`), the criteria, the measured numbers and the report paths. The engine is stopped in every end.
- NEW job `vllm_teacher_check` (experimental, docs/VLLM.md) and error code `vllm_teacher_check_failed`: `{"teacher": {"repo", "load"}, "student", "model": {"family"}, "data", "k", "max_seq", "rows": 100, "seed", "out": ".../vllm_teacher_check.json", "work", "reference_cache": folder of a complete standard cache of the same original (optional), "engine": {"kind": "vllm", "teacher": {...}, "container": {...}}, "stop_file"}`. Compares the vLLM teacher's top-k answers with the standard 4-bit teacher's on N real rows (top-1 agreement, top-k overlap, KL over the shared support, tail mass, by position) and writes the verdict (`same | close | different`, heuristic thresholds written into the file) to `out`. Result keys: `verdict`, `text`, `rows`, `tokens`, `metrics`, `by_position`, `reference`, `identity` (`engine`, `teacher_quant`, `teacher_origin`), `vllm` (`startup_seconds`, `load_seconds`, `tokens_per_s`, `load_phases`, `timings`), `thresholds`, `report`.

## Research follow-ups (additive keys, experimental)

No job, event or error code was added for these; `contract.json` is unchanged. Every key is optional, and a job without them gives the same files, plans and keys as before.

- `distill_cache` result and `distill` summary: `coverage` (what the rows of the heal cover; docs/HEAL_SETTINGS.md), also written as `coverage.json` next to the cache's `index.json`. The cache `index.json` gains `teacher_weights` (the identity of the original's weight files); a store or index without it is accepted once and then carries it. The shared store id has a second version that includes it.
- `reshape_try`: the result key (`key`) gains `weights_sample`; saved answers without it are accepted. `scores.json` gains `weights`; a measurement without it is accepted.
- `reshape` result: `params_breakdown` `{text_layers, embeddings, output, vision, mtp, other, total, mtp_removed}`.
- `distill`: `distill.head_checkpoint` `"on"` (default) | `"off"` (keep the output layer's logits for the backward pass; the `heal_settings` event then carries `settings.head_checkpoint: false`; the same loss, more memory, student-side only, in no cache key).
- `reshape`: `width_scoring` `"activation"` (default) | `"output"`; the result's `width` and `ndforge_reshape.json` `width` carry `scoring: "output"` only then. `reshape_measure` / `scores.json`: `mean_square: true` and the arrays `mlp_ms`, `mlp_ms_h1`, `mlp_ms_h2` in `scores.npz`; `down_norms.npz` next to them.
- `reshape_try`: a choice may carry `scoring: "output"` (needs a width; the plain cut is tried as well); pass keys get an optional suffix segment `|s=output`; the analysis gets `variants` (only when there are some).
- `reshape_try`: a choice may carry `reconstruct` `"pruned"` | `"original"` (needs a width; the plain cut is tried too); pass keys get an optional `|r=pruned` / `|r=original` segment; the results file gets `recon` (per key: tag, variant, median / worst held-out share, layers, tokens, overlap, seconds) and `variants[].recon`; optional job keys `recon_alpha`, `recon_samples`, `recon_len`. Progress step `recon`, timing `recon`. The refit is written next to the measurement as `recon/<tag>/`.
- `reshape`: `reconstruct` `{"variant": "pruned" | "original", "alpha": 0.01}` (width cuts only); the result's `width.recon` and `ndforge_reshape.json` `width.recon` describe it; progress step `recon`.
- `distill`: `bench` `{"steps": 12, "warmup": 3, "targets": "cache" | "synthetic"}` runs the speed test of the healing loss instead of a heal: nothing is saved, no output folder is made; timing `heal_bench` `{tokens_per_s, peak_vram_mb, chunk, head_checkpoint, student_b}` and the same keys (plus `tokens`, `seconds`, `targets`, `max_seq`, `batch`) in the result. No new job type, event or error code.
- `distill_cache`: `holdout` `{"rows": 64}` (general rows read past the ones used, saved as `holdout.npz` + `holdout.json` in the cache folder; the original's loss on them is measured while it is loaded; result key `holdout`). `distill`: `eval.holdout` `{"rows": 64}` makes `distill_eval` carry `holdout_loss` and the summary `holdout_rows`, `holdout_loss_before`, `holdout_loss_after`, `teacher_holdout_loss`.


## vLLM teacher cache (additive keys, experimental)

- `distill_cache` job: optional `engine: {"kind": "vllm", "teacher": {"route": "auto|bnb|prequant", "pairs": {...}, "confirmed": {...}, "quantized_repo", "quantized_rev", "bnb_args", "bnb_pip"}, "container": {engine settings of docs/VLLM.md: kind, image, distro, wslc, exec_templates ...}, "required": bool, "teacher_check": {"verdict"}, "batch_tokens", "llm_kwargs"}`. Absent = the job as it always was. Result key `teacher_engine` `{engine, teacher_quant, used, fallback, problem, startup_seconds, load_seconds, tokens_per_s, load_phases, timings, route, unchecked}`. The index gains `engine`, `teacher_quant`, `teacher_origin` (vLLM caches only); they are part of the cache identity and of the shared store id.
- `vllm_teacher_check` job and error code `vllm_teacher_check_failed`: see above (one entry in `contract.json`).
- `vllm_selftest` report/result: `model_info` (`model`, `params_b`, `params_source`, `weights_gb`, `quant`), `model_params_b`, `model_quant`, `gpu`, `answer_tokens`, `short_answers`, `long_tokens_per_s`, `exit_logs`, `start_command`, `timings`.
- The standalone script `vllm_cache.py` (runs inside the container) prints protocol-shaped JSON lines; its error code `vllm_cache_failed` is internal to the runner and not a worker error code.

## 8-bit KV cache (additive keys, experimental)

`engine.kv_cache_dtype` ("auto" | "fp8") of `think_check` / `trace_gen` / `vllm_selftest` engine objects (result `engine.kv_cache: "fp8"` and a `kv_cache` key in the check's cache key only when fp8); `engine.kv_cache_dtype` + `engine.kv_cache_dtype_teacher: true` of the `distill_cache` engine object (index/identity key `kv_cache: "fp8"` only then); `vllm_teacher_check` job key `kv_cache_dtype` (result `kv_cache_dtype`, `identity.kv_cache`); `vllm_selftest` job key `kv_fp8_test` (report `kv_fp8`); `think_check` (backend llama) job key `cache_type` ("f16" | "q8_0", `flash_attn_args`), result and cache key `llama_cache_type` only when q8_0. No job type, event or error code was added.

## Heal speed measurement (additive keys, experimental)

`distill` job, `bench` object: `profile: true` (result `heal_profile {forward_s, loss_s, backward_s, optimizer_s, gdn_s, gemm_s, top_kernels, ...}`), `microbench: true`, `teacher_bench: true` (needs `distill.teacher {repo, load}`), `out_dir` (the worker writes `heal_speed_report.json/.md` there on every end; result extra `heal_speed_report {report, report_md}`), `windows_hints: [..]`. Result/extras `kernels {delta_rule: fla | torch | unknown, causal_conv1d, how, module}` (`speed.gdn_kernels`). `distill_cache` job key `teacher_batch_tokens` (rows per forward by a token budget; absent or 0 = the fixed `batch`; not part of the cache identity). No job type, event or error code was added.

Additive: a heal-speed report's `environment` has `triton_match` ({torch, triton, wants, source, matches, text}); a failed export or conversion error message ends with the last lines of the tool's output (scrubbed, user name redacted).
